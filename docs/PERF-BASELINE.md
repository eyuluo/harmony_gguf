# 性能基线指标

> 状态同步：2026-10-15。进度见 [STATUS.md](STATUS.md)。本文数值为目标和测量方案；尚无当前快照的真机性能基线。

> 角色 C（质量保障）维护 · Day 7-8 交付物
> 参考：PRD 非功能需求、PLAN-35DAY.md 阶段 1

## 1. 基准模型

本地基准计划使用 TinyLlama-1.1B Q4_K_M；PRD 的旗舰机 7B Q4 目标需单独测量。两种模型的性能不可互相替代，也不能将模拟器冒烟耗时视为 TTFT。

## 2. 指标定义

| 指标 | 目标值 | 测量方法 | 测量时机 |
|------|--------|----------|----------|
| 首字延迟 (TTFT) | < 5s | 首次 generate 到首个 onToken 回调的时间差 | M1 起记录 |
| 生成速度 | 稳定无卡顿 | tokens/s = 生成 token 数 / 总耗时 | M1 起记录 |
| 崩溃率 | < 0.5% | 长对话 20 轮以上统计 | M4 |
| 模型加载成功率 | ≥ 95% | 多次加载统计 | M3 |
| 导入到首对话完成率 | ≥ 80% | 端到端统计 | M3 |

## 3. 测量环境

- 设备：HarmonyOS NEXT 真机（或模拟器）
- 模型：Q4_K_M 量化，context length 512
- 线程数：2（可配置）
- 采样：temperature=0.8, top_k=50, top_p=0.9

## 5. 冒烟测试通过标准

主路径（llama / qwen2）冒烟测试通过条件：
1. 模型加载成功，无崩溃
2. llama_decode 返回 0
3. logits 非空
4. 采样得到有效 token id (≥ 0)
5. token 可解码为文本

## 6. 多模态图片性能与回归

加载参数 `imageMaxTokens` 默认 1024，0 恢复投影器默认，最大 4096。支持动态分辨率的投影器会根据上限调整图片预处理；固定分辨率投影器不保证生效。降低上限减少视觉编码和语言模型 prefill 的计算量，也可能降低文字识别和细节定位准确率。

原生日志记录多模态输入 token 总数、图片解码与预处理准备时间、视觉编码时间、prefill 时间（含 decode 锁等待）。视觉编码通过独立互斥锁保护，不再持有语言模型 decode 锁；decode 与对应采样在同一临界区执行。

真机对比时固定设备、GGUF、mmproj、图片、线程数和文字提示，分别测试上限 512、1024、0，每组至少运行三次并记录冷启动与后续请求的 TTFT。性能改进必须以真机实测为准，不能根据 token 上限比例推算耗时比例。

UI 回归覆盖窄屏和键盘弹出场景、一次选择四张图、移除与重新选择、发送前后缩略图、重启后持久化消息预览、只发送图片、连续多轮以及图片与纯文本请求并发。图片选择器仅提供原生 stb_image 可解码的 PNG、JPEG、GIF；WebP 需额外解码支持，当前不提供选择入口。

## 7. 纯文本 prefill 与多轮边界

每个逻辑槽位绑定一个对话 ID，并保留其最近成功纯文本请求的 KV 与 token 前缀。生成完成仅让出执行机会，对话归属继续保留；应用按提交顺序调度等待对话。同一对话下一轮仅重新计算不匹配的后缀，至少重新计算一个 token；不支持安全 KV 裁剪的架构回退到完整 prefill。容量不足时回收最久未使用的空闲缓存，禁止回收活跃对话；已回收对话再次运行时根据消息历史重建。删除对话清理归属。原生日志输出总输入、复用 token、实际计算 token 和 prefill 耗时（含锁等待）。并发测试覆盖同一对话第二轮、不同对话缓存隔离、空闲缓存回收、删除、停止后重试和模型切换。

验证输入 1024 tokens、输出上限 128、上下文 4096 时可以生成；验证输入等于或超过上下文时使用最近输入窗口；验证输入与输出合计超过上下文时，可位移 KV 架构继续滑动生成。超长输入窗口保留首 token 和最新内容，较早历史与系统提示可能不完整，不能声称保留无限历史。

## 8. CPU 线程池与生成热路径

模型加载后为语言模型创建持久 CPU 线程池，prefill 与 decode 共用，卸载或切换模型时释放。线程数使用已加载上下文的配置，空闲线程通过条件变量等待，避免每次计算图执行创建和销毁线程，以及空闲期间持续轮询。输入 prefill batch 在同一请求内复用，输出 token 文本缓冲在生成循环内复用。

日志分别记录 prefill 的总输入、复用输入、实际计算输入与耗时，以及 decode 的执行步数、计算与锁等待耗时和吞吐。decode 日志不包含输入 prefill 与 UI 回调耗时；界面与 API 的 tokensPerSecond 仍使用请求整体耗时，两者不能直接比较。仅生成一个 token 时通常没有额外 decode 步骤，decode 日志吞吐为 0。

真机回归固定设备、模型、线程数、上下文和采样参数，对比首次长输入、同一对话第二轮及至少 128 tokens 的输出；同时检查停止后重试、交替切换多个对话、卸载与重新加载。没有真机实测前不记录加速比例。

## 9. 已有内存证据与待办

2026-10-15 的 Windows 词表模型回归执行 8 轮加载、缓存分配和卸载，第 4–8 轮卸载后进程私有内存约 5.66–5.94 MiB，未见持续累积。该模型没有权重和推理上下文，也未调用 NNRt；不能据此判断真机内存泄漏。

当前优先记录用户复现的多次加载后卡住、闪退：每轮加载前、推理后、卸载后分别采集私有内存/PSS、模型映射、线程数、耗时和崩溃日志；固定模型、上下文、parallel、线程及 mmproj，分别对照 CPU 和 NPU。区分仍持有资源、分配器保留内存、瞬时峰值和驱动分配，不直接用 RSS 不下降判定泄漏。
