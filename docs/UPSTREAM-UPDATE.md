## 2026-10-15

上游来源为本地 `../llama_cpp`，版本为 llama.cpp 0.6.0-dev、ggml 0.26.0。该目录没有 Git 历史，版本号不能唯一标识源码快照。

按文件同步已移植的引擎、ggml 公共层、ARM/x86 CPU 实现与 mtmd，多模态和 CPU 接口随引擎一起更新。新增 clef、glm5-next、hrm-text、hy-v4、maple、spark2-5 模型实现，加入 ling3vl 视觉实现及 tiled CPU 计算。模型实现进入构建不代表对应权重已通过设备推理验收。

保留项目聊天模板扩展、CPU 后端中的 Harmony NPU 调度入口、OHOS 线程亲和设置，以及应用层、Serve 与会话缓存适配。mtmd 的 llama-ext 引用使用项目 include 路径。

应用与本地测试的 CMake 都生成 `ggml-version.h` 和 `llama-version.h`，构建目录分别持有生成文件，适用于 Debug、Release 和两种 ABI。公共 C++ 包装头 `llama-cpp.h` 按需移植到 engine。

## 加载与卸载资源

加载过程中使用资源守卫持有模型、上下文、线程池和视觉投影器。只有初始化和槽位容器分配全部完成后，资源才移交全局状态；异常和提前返回会释放已经创建的资源。内存分配失败返回 1006，标准初始化异常返回 1003。

卸载与切换模型时释放 token 缓存容量和槽位表，并清空对话归属、使用顺序及重置状态。ArkTS 在原生卸载成功后更新模型状态；卸载任务失败时保留模型句柄，允许再次卸载。

本地回归增加八轮词表模型加载、槽位缓存分配和卸载，检查模型状态及 Windows 进程私有内存。它不能代替真实权重、图片推理及 NNRt 驱动的设备内存检查。

本地全量测试构建补齐 mtmd 与 vendor/hash 依赖，并把原有六组基础测试纳入 CTest。MinGW 在带 AVX2 的普通结构复制中出现栈对齐崩溃，因此测试构建对引擎、业务逻辑和 mtmd 使用 128 位自动向量化偏好；ggml CPU SIMD 内核继续按原选项编译，鸿蒙构建不受此测试配置影响。

上游词表专用加载不再填充训练上下文时，槽位长度采用 4096 默认上限，再按显式加载配置限制，避免本地词表生命周期回归得到零上下文。该回退不改变带有效训练上下文模型的长度限制。

12 组通过包含用例内的 4 项跳过：缺少真实权重的 TinyLlama/Qwen2 推理，以及两项 KV decode 检查。本轮没有安装依赖，也没有执行设备模型推理、Serve 网络回归或 NNRt 真机内存测试。

用户报告 CPU/NPU 配置下多次加载后卡住、闪退。本轮修复了异常资源清理和卸载状态管理缺口，但词表模型回归不能证明这一设备问题已经解决。仍需使用出现问题的真实 GGUF、加载参数及崩溃记录复测，区分内存累积、内存峰值、驱动问题和其他崩溃原因。
