# CPU/NPU 混合计算

> 状态同步：2026-10-15。进度见 [STATUS.md](STATUS.md)。混合执行代码、双 ABI Release 构建和本地策略测试通过；真机加速收益及驱动内存释放尚未验证。

## 实现范围

应用继续直接读取 GGUF。`common/harmony_npu.cpp` 在 ggml CPU 后端提交计算图时，把连续可映射节点构造成 NNRt 模型并在专用加速器上执行。CPU 保留 tokenizer、采样、请求管理、KV 状态与未映射计算。路径不按架构名称限制，语言模型、Serve 和视觉编码均可使用。当前收益筛选要求子图包含至少 32 行输入、至少约 3200 万次乘加的矩阵计算；单 token decode 和只有小算子的图直接执行完整 CPU 图。

当前映射矩阵乘法、标准广播的加减乘除、平方、平方根、RMSNorm，以及 abs、neg、relu、sigmoid、tanh、exp、SiLU。RMSNorm 和 SiLU 分解为 NNRt 基础算子。ggml 特有的周期广播、批维分组重复、Attention、RoPE、MoE 专用算子等仍由 CPU 执行；所有模型继续使用原计算图，不能将此理解为全部算子已获得 NPU 加速。

矩阵维度按 ggml 存储顺序反转为 NNRt ND，矩阵乘法使用输入乘权重转置，保留批维广播语义。FP32 非连续输入按逻辑步长打包。F16、BF16 与 ggml 提供反量化转换函数的权重按行转换为 FP32；设备子图使用 FP32，不直接执行 GGUF 块量化。只有权重缓冲中的数据作为编译常量，其余输入每次更新。

保留 CPU 权重重排优化，不能为启用 NPU 而降低 CPU 回退路径速度。已经存入 CPU 专用重排缓冲的权重继续在 CPU 计算，避免将重排后的数据误按原始 GGUF 布局解码。

## 缓存与回退

运行时通过 `dlopen/dlsym` 查询 NNRt 接口，不强制链接 NPU 系统库。只有枚举为专用加速器的设备参与执行；没有接口或加速器时使用原 CPU 整图执行。NNRt 接口通过全局互斥锁串行调用。

子图上限为 32 个连续节点，缓存最多 128 个执行计划，转换权重、中间计算和共享缓冲的预算估算上限为 256 MiB。超大子图尝试拆分，仍超限的计算回退 CPU。该预算只约束应用估算的缓存，不等于驱动内部内存上限。达到总预算时保留已有计划，其余子图使用 CPU，避免逐 token 驱逐和重新编译。

缓存键包括算子、参数、形状、输入类型与步长、连接关系、常量权重地址和输出边界。缓存执行器与共享输入输出缓冲，首次执行后与 CPU 子图结果逐元素对照，通过有限值及误差门槛后才复用。编译、执行或对照失败时销毁对应计划并记录拒绝键，当前计算由 CPU 重算。切换或卸载模型前等待生成结束并清空缓存，防止复用旧权重。

首次对照同时记录 NPU 输入打包、执行、输出读取与 CPU 执行耗时，编译时间单独排除。只有 NPU 测量耗时比 CPU 降低至少 20% 才保留执行计划；否则销毁计划并记住该子图，后续使用 CPU。首次对照直接使用已计算的 CPU 结果，不重复计算或写回可能已复用的中间缓冲。未卸载的相邻节点合并为 CPU 图段，减少计算图拆分开销。该策略是首次测量的保守筛选，不能保证温度与负载变化后仍有同样收益；首次编译成本依然存在。

CPU 分配器管理图张量的生命周期。NPU 只向 CPU 写回后续节点依赖的子图边界、显式输出与最后一个节点；内部临时计算留在 NNRt 图内。NNRt 同步调用期间不能保证立即取消，停止标志在设备调用前后和子图之间检查。

## 使用与验证

用户报告 CPU/NPU 配置下多次加载后卡住、闪退，当前仍待真机复现。加载失败会清理已创建资源和 NPU 状态；卸载清空执行计划。共享缓冲容器先预留容量，避免缓冲创建后因容器扩容异常而失去所有权。这些修复不构成设备问题已解决的证据。

模型加载弹窗中的“NPU 加速”默认开启，关闭并重新加载可对照纯 CPU。设置通过 Preferences 保存。`getAccelerationStatus()` 可查询设备、成功子图次数、回退次数和缓存估算。发现设备不等于模型可以加速；应以成功执行次数和端到端耗时为依据。

页面顶部展示实际计算摘要，点击可查看设备名、NPU 输出采用次数、回退次数、CPU 整图次数、最近子图的 CPU/NPU 对照耗时及失败原因。首次数值与性能对照采用 CPU 输出，不计入 NPU 加速执行次数。状态在模型加载和对话结束时更新，计数为本次模型加载以来累计，不是当前单轮统计。单 token 输出目前使用 CPU，开启 NPU 不代表逐字输出速度会提高；应重点比较相同长输入的首字等待时间。

真机验证应覆盖手机、平板和 2-in-1，不同芯片及系统版本分别记录结果。固定 GGUF、图片、输入历史、线程数、上下文和采样参数，对比开启与关闭 NPU 的首字延迟、prefill、decode、内存与发热；同时验证同一对话多轮、跨对话、请求停止、卸载重载及 Serve 并发。

首次遇到新形状时包含编译和 CPU 对照开销，应分别记录首次与缓存后性能。当前实现尚无真机加速数据，不能承诺全部设备、全部量化类型或全部算子均可使用 NPU。
