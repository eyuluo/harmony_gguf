# Harmony-GGUF — PRD（产品需求文档）

> 版本：v0.1 · 关联文档：`mvp.md`（功能范围）、`TDD.md`（技术设计）

## 1. 产品概述

### 1.1 背景
当前移动端本地大模型运行方案（llama.cpp / Ollama 生态）主要集中在 Android / iOS，HarmonyOS 生态缺乏成熟的 GGUF 运行器。随着 HarmonyOS NEXT 设备增长，用户需要一个可在鸿蒙设备上离线运行本地大模型的工具。

### 1.2 产品定位
一个纯本地、离线的 GGUF 大模型运行器，让 HarmonyOS 用户像使用聊天应用一样，在本机运行开源大模型，数据全程不出设备。

### 1.3 目标用户
- **AI 爱好者 / 开发者**：希望在鸿蒙手机上跑开源模型、测试量化效果。
- **隐私敏感用户**：不愿将对话数据上传云端的用户。
- **离线场景用户**：无网/弱网环境下需要 AI 助手的用户。

## 3. 功能需求

### 3.1 模型管理
- FR-01 支持通过系统文件选择器导入 `.gguf` 文件。
- FR-02 解析并展示 GGUF 元数据（架构、tokenizer、上下文长度、量化等级、参数量）。
- FR-03 支持删除已导入模型，并清理占用的存储空间。
- FR-04 展示每个模型的存储占用。

### 3.2 推理引擎
- FR-05 加载 GGUF 模型并通过校验。
- FR-06 支持 BPE / SentencePiece tokenizer。
- FR-07 支持采样参数：temperature、top-k、top-p、repetition penalty。
- FR-08 以流式方式逐 token 输出结果。

### 3.3 对话界面
- FR-09 支持多轮对话，维护上下文历史。
- FR-10 流式打字机效果展示回答。
- FR-11 支持新建会话、切换会话、清空上下文。
- FR-12 支持停止生成、复制回答、重新生成。

### 3.4 参数配置
- FR-13 可配置上下文长度（context length）。
- FR-14 可配置最大生成长度（max tokens）。
- FR-15 可配置线程数 / CPU 核心数。

### 3.5 会话历史（P1）
- FR-16 会话持久化到本地存储。
- FR-17 会话列表与历史记录浏览。

### 3.6 性能监控（P1）
- FR-18 显示首字延迟（TTFT）与生成速度（tokens/s）。
- FR-19 显示内存占用与模型加载进度。

### 3.7 本地 API 服务（Serve）（P1）
- FR-20 可启动 / 停止本地 HTTP 服务器，监听 localhost 或局域网。
- FR-21 提供 OpenAI 兼容接口（`/v1/chat/completions`、`/v1/completions`、`/v1/models`）。
- FR-22 支持流式响应（SSE / Server-Sent Events）。
- FR-23 展示访问地址（IP:端口），支持端口配置。
- FR-24 支持请求鉴权（可选 API Key）。
- FR-25 支持单独启动 Serve（无需进入对话界面），运行状态与对话推理解耦，可后台保持。

### 3.8 内置模型注册表（P1）
- FR-26 内置主流开源模型清单（llama / qwen / gemma / mistral / deepseek / chatglm 等）。
- FR-27 每个条目包含模型 id、架构、聊天模板（chat template）、推荐量化、默认采样参数。
- FR-28 导入 / 下载模型时按架构自动匹配注册表，应用默认配置。
- FR-29 注册表支持版本化与用户自定义扩展。

## 4. 非功能需求

| 类别 | 需求 |
|------|------|
| 性能 | 首字延迟 < 5s（CPU、7B Q4 模型、旗舰机）；流式输出稳定无卡顿 |
| 隐私 | 全程离线，无任何网络请求（除用户主动下载模型） |
| 稳定性 | 长对话不崩溃；内存不足时优雅降级提示 |
| 安全 | Serve 默认仅监听 localhost；局域网监听需显式开启，支持可选 API Key 鉴权 |
| 兼容性 | 支持 HarmonyOS NEXT（API 12+）主流设备 |
| 可用性 | 模型导入到可对话流程 ≤ 3 步 |

## 5. 用户核心流程

```
打开 App
  → 导入 GGUF 模型（文件选择器 / 下载）
  → 选择模型并加载（展示进度）
  → 进入对话页
  → 输入问题 → 流式输出回答
  → 调整参数 / 切换会话 / 停止生成
```

## 6. 验收标准（MVP）

1. 用户能导入一个 GGUF 文件并看到模型元数据。
2. 模型能成功加载并进入可对话状态。
3. 输入文本后，模型能流式返回回答。
4. 调整 temperature / context 等参数后效果生效。
5. 全程无网络请求（可断网验证）。

## 6.1 验收标准（P1 / Serve）

1. 启动 Serve 后，本机可通过 `curl http://127.0.0.1:PORT/v1/models` 获取模型列表。
2. 可通过 `POST /v1/chat/completions` 获取流式回答（SSE）。
3. 开启局域网监听后，同网段设备可访问并完成一次对话。

## 7. 成功指标（MVP 后评估）

- 模型加载成功率 ≥ 95%。
- 首字延迟中位数 < 5s。
- 崩溃率 < 0.5%（长对话 20 轮以上）。
- 用户从导入到首次对话完成率 ≥ 80%。
